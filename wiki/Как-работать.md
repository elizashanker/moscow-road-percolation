# Как работать с проектом

## С чего начать

1. Откройте представление «Можно брать» на доске GitHub Projects.
2. Выберите задачу, которую готовы выполнить, и договоритесь с командой, кто будет проверять результат.
3. Прочитайте блоки «Перед началом» и «Куда положить результат». Если входной файл ещё не готов, сначала уточните это в комментарии.
4. Поставьте себя исполнительницей и перенесите задачу в «В работе».
5. Выполняйте шаги задачи. Если меняете правило эксперимента, обсудите это с командой и обновите `docs/decisions.md`.
6. Сохраните результат по указанному пути, загрузите нужные файлы и оставьте ссылку в задаче.
7. Перенесите задачу в «Проверка». Проверяющая сверяет результат с критериями и только затем переводит её в «Готово».

Если GitHub-ники ещё не добавлены, договорённость об исполнительнице можно временно записать комментарием.

## Что означает путь к файлу

Все пути в задачах начинаются от главной папки проекта. Например, `docs/data-check.md` означает: открыть папку `docs` и создать или изменить в ней файл `data-check.md`.

Обозначение `<район>` заменяется на `khamovniki` или `basmanny`, а `<сценарий>` — на `random` или `local`. Например: `reports/tables/runs_khamovniki_random.csv`.

Указанные в задачах файлы — ожидаемые результаты. Их отсутствие до выполнения задачи нормально. Нельзя создавать пустую таблицу и выдавать её за выполненный расчёт.

## Куда что сохранять

| Что сделали | Куда положить |
|---|---|
| Правило, проверка, заметка, объяснение решения | `docs/` |
| Программа, которая будет использоваться повторно | `src/road_percolation/` |
| Команда запуска или отдельный исполняемый сценарий | `scripts/` |
| Исследовательский блокнот | `notebooks/` |
| Исходная выгрузка OSM | `data/raw/`, обычно только локально |
| Подготовленный граф | `data/processed/`, обычно только локально |
| Таблица измерений | `reports/tables/` |
| Карта или график | `reports/figures/` |
| Основной текст научной статьи | `paper/manuscript.md` |
| Подпись и сведения о происхождении рисунка | `paper/figures.md` |
| Презентация и заметки выступления | `reports/presentation/` |
| Окончательные файлы для сдачи | `reports/final/` |

`.md` — обычный текстовый файл с простым форматированием. Его можно редактировать прямо на GitHub кнопкой с карандашом. `.csv` — таблица, которую открывают Python и табличные редакторы. `.graphml` — сохранённый граф, а не рисунок карты.

## Как загрузить небольшой текст или рисунок через сайт

1. Откройте нужную папку репозитория.
2. Для нового файла выберите **Add file → Create new file** или **Upload files**. Для существующего текста — кнопку с карандашом.
3. Дайте файлу понятное имя из задачи. Большие исходные графы через сайт не загружайте.
4. Если GitHub предлагает создать отдельную ветку и pull request, выберите этот вариант. Pull request — предложение изменить файлы, которое можно проверить до принятия.
5. В описании напишите номер задачи и что получилось. Например: «Для #4 проверены границы двух районов, добавлена картинка и список OSM ID».
6. Оставьте ссылку в задаче и попросите другую участницу проверить.

Файлы в `reports/tables/` и `reports/figures/` по умолчанию не добавляются автоматически из локальной копии: так мы защищаем репозиторий от тысяч промежуточных результатов. Небольшой согласованный итог можно добавить через сайт или командой `git add -f <конкретный файл>`. Никогда не используйте принудительное добавление всей папки без просмотра содержимого.

## Как отчитаться в задаче

Скопируйте и заполните:

```text
Что сделано:
Где результат: ссылка на файл или pull request
Как проверено:
Что осталось непонятно:
Проверяющая:
```

Для локальных данных укажите имя файла, контрольную сумму и где команда может получить эту же выгрузку. Если используете общую папку вне GitHub, ссылку и права доступа согласуйте отдельно.

## Несколько слов из задач

- **Граф:** модель из точек и соединений. Здесь точки — перекрёстки, соединения — участки дорог.
- **Компонента:** группа точек, между любыми двумя из которых остался путь.
- **q:** доля закрытых участков. Например, q=0.2 означает 20%.
- **S1:** доля исходных точек в самой большой компоненте.
- **S2:** доля исходных точек во второй по размеру компоненте.
- **Seed:** число, позволяющее повторить тот же случайный выбор.
- **Конфигурация:** файл с параметрами запуска, например числом повторов.
- **Порог:** выбранная оценка момента распада; в нашем протоколе — максимум средней S2.

## Статья пишется всё время

После задачи не ограничивайтесь картинкой или CSV. Добавьте понятную заметку о том, что сделали, либо передайте её автору соответствующего раздела. В задаче указан вклад в статью. Основной текст ведём в одном файле `paper/manuscript.md`.
